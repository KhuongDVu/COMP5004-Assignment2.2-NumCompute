# COMP5004-Assignment2.2-NumCompute

An extension of `numcompute`: supports chunk-wise updates through `.partial_fit()` / `.update()`, plus a from-scratch decision tree that retrains itself periodically from a buffer.

## Setup & Installation

### 1. Clone the Repository

```bash
git clone https://github.com/KhuongDVu/COMP5004-Assignment2.2-NumCompute.git
cd COMP5004-Assignment2.2-NumCompute

```

### 2. Create and Activate Virtual Environment

* **macOS / Linux:**
```bash
python3.11 -m venv .venv
source .venv/bin/activate

```


* **Windows (PowerShell):**
```powershell
py -3.11 -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1

```


### 3. Install Package

Install `numcompute` in editable mode with development dependencies:

```bash
pip install --upgrade pip
pip install -e ".[dev]"

```

## API Overview

| Module | Key Functions / Classes | Purpose |
| --- | --- | --- |
| `stats.py` | `StreamStats` | Running count/mean/variance via a vectorised Welford merge, folded in chunk by chunk. |
| `metrics.py` | `StreamingAccuracy`, `StreamingConfusionMatrix`, `StreamingPrecisionRecallF1`, `StreamingAUC`, `RollingMetric` | Chunk-wise counterparts to `numcompute.metrics`, updated via `.update()`. |
| `preprocessing.py` | `StreamingStandardScaler`, `StreamingImputer`, `StreamingOneHotEncoder` | Scaling, imputation, and one-hot encoding with running statistics instead of a single batch fit. |
| `tree.py` | `DecisionTreeClassifier` | Binary decision tree (Gini/entropy); `partial_fit` buffers chunks and retrains from scratch once `buffer_size` rows have accumulated. |
| `pipeline.py` | `Pipeline` | Chains streaming transformers with a final streaming model, driven one chunk at a time via `partial_fit`. |
| `stream.py` | `StreamTrainer` | Drives any streaming estimator or `Pipeline` chunk by chunk, logging per-chunk accuracy, cumulative accuracy, and estimated memory use. |
| `visualise.py` | `plot_metric_over_time`, `compare_models`, `plot_predictions_vs_ground_truth` | Matplotlib helpers for metrics over time, model comparisons, and predictions vs ground truth. |

## Running the Demo

```bash
jupyter notebook demo/stream_demo.ipynb
```

Generates a synthetic 2000-row classification dataset to `demo/stream_dataset.csv`, streams it through a `Pipeline` in 100-row chunks via `numcompute.io.load_csv_chunks`, trains incrementally with `partial_fit`, and visualises accuracy over time, a prediction-vs-ground-truth scatter, and a `buffer_size` comparison with `visualise.py`.

## Running the Streaming Benchmarks

```bash
python3 benchmark/run_stream_benchmarks.py
```

Regenerates `benchmark/stream_split_search_results.csv`, `benchmark/stream_buffer_sweep_results.csv`, and `benchmark/stream_environment.txt`.

### Loop vs NumPy split search

The decision tree's threshold search compared against a loop-based reimplementation of the same algorithm:

| Samples | Loop (ms) | NumPy (ms) | Speedup |
| --- | --- | --- | --- |
| 20 | 0.0798 | 0.0179 | 4.46x |
| 100 | 0.4135 | 0.0177 | 23.43x |
| 300 | 1.4086 | 0.0230 | 61.24x |
| 600 | 3.2678 | 0.0345 | 94.80x |

### buffer_size sweep

Streaming a 5000-row synthetic dataset in 50-row chunks through `DecisionTreeClassifier`, for several `buffer_size` values:

| buffer_size | n_retrains | avg_retrain_ms | test_accuracy |
| --- | --- | --- | --- |
| 50 | 100 | 0.5620 | 0.757 |
| 200 | 25 | 1.0183 | 0.830 |
| 500 | 10 | 1.3722 | 0.829 |
| 1000 | 5 | 1.9567 | 0.847 |
| 2000 | 2 | 3.0055 | 0.845 |

A larger `buffer_size` means fewer, more expensive retrains (more buffered rows to rebuild the tree from each time) but a more stable sample to learn from; a smaller `buffer_size` retrains cheaply and often, but each retrain sees less data at once.

*Execution environment: Python 3.10.0; NumPy 2.2.6; macOS-14.2.1-arm64-arm-64bit; arm64.*
